**전체 그림 (적용 단계별)**

검색 전(Pre-retrieval) : HyDE, Query Expansion

검색 중(Retrieval) : Hybrid Search

검색 후(Post-retrieval): Reranking

대화형 : Conversational RAG

**Hybrid Search (하이브리드 검색)**

Dense 검색(의미)과 Sparse 검색(키워드)을 결합해, 두 방식의 장점을 동시에 활용하는 검색 기법

*   사용 이유 : Dense만 쓰면 정확한 키워드("GPT-4o")를 놓치고, Sparse만 쓰면 의미가 같은 표현("자동차"-"차량")을 놓치기 때문
    
*   동작 방식
    
    *   1\. Dense 검색: 의미 유사도로 Top-K
        
    *   2\. Sparse 검색: 키워드 매칭(TF-IDF/BM25)으로 Top-K
        
    *   3\. 두 점수를 0~1로 정규화 후 가중 합산 final\_score = alpha _dense + (1 - alpha)_ sparse
        
    *   4\. 결합 점수로 최종 순위 결정 alpha = Dense 비중 (보통 0.5~0.7이 균형, 실무 기본값)
        

**Query Expansion (질의 확장)**

원본 질문을 재구성하거나 관련 용어를 추가해 검색 범위를 넓히는 기법이다. (검색 전 단계)

*   사용 이유 : 질문이 짧거나 모호하면 임베딩에 담기는 정보가 부족해, 관련 문서를 놓칠 수 있기 때문
    
*   종류
    
    *   유의어 추가: 약어/유의어를 덧붙임 (RAG -> Retrieval-Augmented Generation)
        
    *   Multi-Query: 여러 관점의 질문으로 재작성해 각각 검색 후 통합 (수평 확장)
        
    *   Step-back: 더 일반적인 상위 질문으로 바꿔 검색 (수직 확장)
        

**Reranking (재순위화)**

1차 검색으로 뽑은 후보 문서를 정밀 모델로 다시 평가해, 관련성 높은 순서로 재정렬하는 기법이다. (검색 후 단계)

*   사용 이유 : 빠른 1차 검색은 무관한 문서가 섞이기 쉬워, 상위 결과의 정밀도를 높여야 답변 품질이 올라가기 때문
    
*   동작 방식
    
    *   1차 검색(Bi-Encoder): 질문/문서를 따로 벡터화 -> 빠름, 정확도 낮음  
        재순위화(Cross-Encoder): 질문+문서를 함께 입력 -> 느림, 정확도 높음
        
    *   Bi-Encoder로 Top-N 빠르게 확보 -> Cross-Encoder로 그 후보만 재평가 -> Top-K 선택
        

**HyDE (Hypothetical Document Embeddings)**

질문으로 가상의 답변 문서를 먼저 만들고, 그 답변을 임베딩해 실제 문서를 검색하는 기법이다. (검색 전 단계)

*   사용 이유 : 짧은 질문은 설명형 문서와 벡터 거리가 멀어, 답변형 텍스트로 바꾸면 실제 문서와 더 가까워지기 때문
    
*   동작 방식
    
    *   1\. LLM이 질문에 대한 가상 답변 생성
        
    *   2\. 가상 답변을 임베딩
        
    *   3\. 그 벡터로 실제 문서 검색
        
    *   4\. 검색된 실제 문서로 답변 생성  
          
        포인트 : 가상 답변이 사실과 틀려도 됨. 의미 방향만 맞으면 검색이 잘 됨
        

**Conversational RAG (대화형 RAG) ★ 알렉스 강조: 실무에서 가장 중요 ★**

이전 대화 기록을 참고해 현재 질문을 독립형 질문으로 재구성한 뒤, 검색과 답변을 수행하는 멀티턴 RAG다.

*   사용 이유 : "그것", "가격은?" 같은 맥락 의존 표현은 그대로 검색하면 의미 정보가 없어 검색에 실패하기 때문
