위클리 내용 : 미니GPT 대화형 전환 (위키 학습 -> 대화 데이터 재학습)

*   직접 만든 미니GPT를 처음엔 한국어 위키백과 데이터로 학습했다.
    
*   문제 : 학습은 잘 됐는데(loss 0.36) 막상 대화가 안 됐다.
    

위키 모델 실제 출력 ("오늘 너무 피곤해" 입력)

    오늘 너무 피곤해, 케플러, MCD-893년 키릴레이식 3세인 발트.
    (1893년~) 8월 20일 - 독일의 화학자, 경제학자 빌프레드 보비.
    (1895년~) 8월 14일 - 대한민국의 기업인 김영일. (1840년~)
    9월 26일 - 일본의 영화감독 조지프 L. 맹키위츠. (1882년~)
    ...
    
    -> 인물 이름 + 연도 + 날짜 나열 (위키 "사망/출생" 문서 패턴)
    -> 대화가 아니라 백과사전 문장이 나옴

원인 : 위키는 "설명문"이라 모델이 설명체만 배웠다.

해결 방향 : 과제 의도("다음 단어 생성 모델 직접 만들기")에 맞춰 대화 데이터로 다시 학습시키기로 하였습니다.

    참고: 위키 loss 0.36이 낮았던 건 잘 배운 게 아니라
          문자 단위 + 작은 데이터를 외운 것(과적합)에 가까움

1단계 : 대화 데이터 준비

허깅페이스의 한국어 instruction 데이터셋을 받았습니다.

    from datasets import load_dataset
    ds = load_dataset("nlpai-lab/kullm-v2", split="train")
    # 데이터 15만 2630개

데이터 구조

    {'instruction': '질문', 'input': '', 'output': '답변'}
    -> 질문(instruction) + 답변(output) 쌍

대화 형식으로 변환 : 누가 말하는지 구분되게 토큰을 붙였

    <사용자> {질문}
    <봇> {답변}
    
    (input이 있으면 질문에 합치고, 빈 것/500자 초과는 제외)

결과 : 대화 7만 2440개 / 2646만 자 (chat\_data.txt)

    이렇게 하면 모델이
    "<사용자> 다음엔 질문, <봇> 다음엔 답변" 패턴을 배움

2단계 : v1 학습 (대화 성공 확인)

위키 학습 코드에서 데이터 파일만 바꿔서 재학습했다.

    big_data.txt -> chat_data.txt
    save_dir도 분리 (위키 모델과 안 섞이게)

핵심 : vocab을 새로 만들어야 함. 대화 데이터는 글자 종류가 위키와 다르므로 stoi/itos가 바뀜.

결과 : loss 8.39 -> 1.76 (5만 step)

테스트 : 반드시 대화 형식으로 입력해야 한다.

    generate(model, "<사용자> 오늘 너무 피곤해\n<봇>")
    
    "안녕" -> "안녕하세요! 오늘은 무엇을 도와드릴까요?"
    -> 인사에 인사로 반응! 대화 패턴 학습 성공
    
    그냥 "오늘 너무 피곤해"만 넣으면 위키 때처럼 이상하게 나옴
    -> "<사용자> ...\n<봇>" 까지 줘야 봇이 답할 차례임을 인식

3단계 : v2 학습 (모델 키우기)

대화는 됐지만 가끔 횡설수설해서, 모델을 키워 재학습했다.(2번 바꿨어요...)

설정 변경

    n_embd     64 -> 384 -> 512   (표현력)
    n_head     4  -> 6   -> 8     (n_embd 나눠떨어지게)
    n_layer    2  -> 6   -> 8     (깊이)
    block_size 8  -> 256
    max_iters  5만 -> 10만         (2배 학습)

주의 : n\_embd는 n\_head로 나눠떨어져야 한다는 것을 알았습니다.

    512 / 8 = 64  (OK)
    512 / 6 = 85.3 (에러)

**트러블슈팅 모음(이 부분은 AI를 통해 해결하였으며, 이 문단 또한 AI의 도움을 받아 정리 하였습니다.)**

1.  설정을 고쳐도 모델이 안 커짐 (파라미터 13.8M) 원인 : 하이퍼파라미터만 바꾸고 model = MiniGPT()를 다시 안 돌림 -> model은 옛날 설정 그대로 해결 : 설정 셀부터 model 생성 셀까지 다시 실행 ("이후 셀 실행" 메뉴가 편함)
    
2.  학습 셀이 max\_iters를 덮어씀 원인 : 학습 셀 안에 max\_iters = 50000 줄이 또 있어 하이퍼파라미터 셀의 10만을 무시 해결 : 학습 셀의 중복 줄 삭제, lr도 learning\_rate 변수로 통일
    
3.  셀 실행 순서로 block\_size가 덮어써짐 원인 : block\_size=8 셀이 하이퍼파라미터(256)보다 나중에 실행되면 8로 돌아감 해결 : 하이퍼파라미터 셀을 더 나중에 실행해 256 유지
    
4.  저장공간 부족 (학습 중 발생) 원인 : 1000step마다 minigpt\_{iter}.pth 백업이 쌓여 드라이브가 꽉 참 (모델이 커져서 파일 하나가 수십 MB) 증상 : "자동 문서 저장 중단" 경고 주의 : 새로고침하면 런타임 끊겨 메모리의 모델이 날아감 -> 절대 X 해결 : 학습은 메모리에서 도니까, 새 셀로 번호별 백업만 삭제 (latest.pth는 이어학습용이라 보존)
    
         import os, glob
         files = glob.glob(f"{save_dir}/minigpt_*.pth")
         for f in files:
             os.remove(f)

인사/감사 응답

한계 (정상)

    덜 흔한 입력은 여전히 횡설수설
    -> 미니GPT라 작고, 문자 단위 토크나이저라
       단어 의미보다 "그럴듯한 글자 나열"에 가까움

5단계 : generate 수정 (출력 정리)

문제 : 첫 답변 후 모델이 멋대로 다음 <사용자> 질문을 지어내며 횡설수설.

원인 : 생성이 멈추지 않고 max\_new\_tokens만큼 계속 이어 씀.

해결 : 첫 <봇> 답변만 잘라낸다.

    result = decode(idx[0].tolist())
    answer = result[len(start_text):]      # 입력 부분 제거
    answer = answer.split("<사용자>")[0]    # 다음 질문 전까지만
    answer = answer.strip()
    return answer
    
    모델이 못한 게 아니라 "언제 멈출지"를 안 알려준 것
    -> split으로 첫 답변만 깔끔하게 출력

마무리 : 저장과 정리

모델 저장 : 가중치와 vocab을 함께 저장해야 나중에 복원 가능.

    torch.save(model.state_dict(), 'minigpt.pth')   # 두뇌
    # vocab_info.json : 글자<->숫자 변환표 + 설정
    
    둘 다 있어야 모델을 다시 쓸 수 있음 (한쪽만으론 무용지물)

내 컴퓨터로 다운로드 : 콜랩은 클라우드라 직접 받아야 안전.

    from google.colab import files

드라이브 정리 : 학습 끝나고 모델 다운받았으니 체크포인트 폴더 삭제.
