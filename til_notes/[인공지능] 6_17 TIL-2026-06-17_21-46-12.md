RAG 평가(RAG Evaluation, LLM-as-a-Judge)

**RAG Evaluation( RAG 평가 )**

*   RAG 파이프라인의 검색 품질과 생성 품질을 정량 지표로 측정하는 과정
    
*   사용 이유 : 어느 단계에서 품질이 떨어지는지 진단하고, "느낌"이 아니라 숫자로 개선 방향을 정하기 위해
    
*   핵심 : 검색과 생성을 나눠서 평가함
    

\-- - **4개 지표**\--------------------------------------------------------------------

\[검색 품질 (Retrieval)\]

Context Precision : 검색 결과 중 관련 있는 비율 (노이즈가 적은가)

Context Recall : 필요한 정보 중 검색된 비율 (빠뜨리지 않았는가)

\[생성 품질 (Generation)\]

Faithfulness : 답변이 문맥에 충실한가 (업ㅅ는 내용을 지어내지 않았는가 = 환각 체크 )

Answer Relevancy : 답변이 질문 의도에 맞는가

\-- -------------------------------------------------------------------------------

\-- --**평가 데이터셋 4요소**\----------------------------------------------------------

question : 질문 (사람이 작성)

ground\_truth : 정답 (사람이 작성)

contexts : 검색된 문맥 (파이프라인이 생성)

answer : 생성된 답변 (파이프라인이 생성)

\-- -------------------------------------------------------------------------------

\-- --결과 해석 예시-----------------------------------------------------------------

검색 실패 : Precision 낮음 + Recall 낮음 -> 임베딩/청킹 개선, Hybrid Search

검색 노이즈: Recall 높은데 Precision 낮음 -> Reranking 도입

생성 실패 : 검색은 좋은데 Faithfulness 낮음 -> 프롬프트/모델 개선

답변 이탈 : 다 좋은데 Answer Relevancy 낮음 -> 질문 의도 재확인 지시

\-- ---------------------------------------------------------------------------------

LLM-as-a-Judge(LLM 기반 평가)

*   LLM에게 채점 프롬프트를 주어 RAG 평가 지표를 자동으로 판단하게 하는 평가 기법
    
*   사용이유 : 규칙 기반 평가는 표현이 조금만 달라도 같은 의미를 다르게 보기 떄문 (의미 판단 불가)
    
*   문제 상황 (규칙 기반의 한계)
    
    *   문맥: "개발 교재 서빙 서비스"
        
    *   답변: "교재를 제공하는 서비스"
        
    *   \-> 의미는 같은데 글자가 달라 Faithfulness 0.00 (억울하게 0점)
        

*   해결 (LLM-as-a-Judge)
    
    *   LLM은 두 표현이 같은 의미임을 이해함 -> 의미 수준에서 정확히 평가 (1.00)
        

동작 방식

1\. 채점 프롬프트 작성 (기준 + 평가 대상: 질문/문맥/답변)  
2\. LLM API에 전달  
3\. 응답(점수)을 파싱해 숫자로 변환

채점 프롬프트 설계 원칙

*   명확한 기준 : "문맥에 명시적으로 있으면 높은 점수" (모호한 표현 X)
    
*   단순한 출력 : "0~1 소수만 출력" (파싱 쉽게)
    
*   역할 부여 : "당신은 RAG 품질 평가자입니다"
    

규칙 기반 vs LLM-as-a-Judge

*   규칙 기반 : 빠름/저렴, 의미 이해 불가 -> 1차 점검용
    
*   LLM-as-Judge : 느림/비용, 의미 이해 가능 -> 정밀 평가용
    
*   \-> 대체가 아니라 역할 분담
