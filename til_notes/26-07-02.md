## edge vs 조건부 edge

edge : 한 노드 실행 끝나면 -> 다음 노드 지정

예 )

    graph.add_edge("search", "generate")
    # -> search끝나면 무조건 generate
    # 핵심 : 다음 목적지가 미리 고정 돼 있음
    

조건부 edge : 한 노드 실행 끝나면 -> 그때의 state 값을 보고 -> 다음 노드를 그때 결정함

핵심 : 다음 목적지가 "실행 중에 정해짐"

\[judge\] ------> \[search\] (검색 필요하면)  
|---> \[generate\] (필요 없으면)

이때 state 보고 결정함 그래서 누가 결정하냐? route 함수

조건부 edge에는 "결정하는 함수" 가 붙음

### Route 함수가 하는 일 :

1.  State를 받는다
    
2.  값을 확인하고
    
3.  다음 노드 이름을 문자열로 반환한다
    

    # 결정 함수 (노드 아님)
    def route(state: RAGState) -> str:      # state값 확인
    	if state["needs_search"]:           # search로 보내기
    		return "search"
    	else:
    		return "generate"               # generate로 보내기
    		
    # 조건부 엣지 등록
    graph.add_conditional_edges("judge", route, ["search", "generate"])
    

    
    # 일반 엣지 : 목적지를 "코드 짤 때 정함"
    graph.add_edge("search", "generate")
    
    # 조건부 엣지 : 목적지를 "실핼할 때" 정함
    graph.add_conditional_edges("judge", route, ["search", "generate"])
    # route 가 실행 중 결정함
    

### 실행 흐름으로 보기

#### 질문 : 파이썬이 뭐야??

    \-> LLM이 판단  
    \-> State 에 need\_search=True 저장
    
2.  조건부 엣지 차례  
    \-> route(state) 실행됨  
    \-> state\["needs\_search"\]가 true?

3.  search 노드로 이동

    \-> LLM : 검색 필요 없

    \-> False? -> return "generate"
    
3.  search 건너뛰고 generate로 직행

### 8\. 코드 짜는 도중에 AI에게 물어본 질문

#### 질문 1 : dict vs str 차이 (route 함수에서)

    
    str = 문자열 (글자)
    "search", "안녕", "파이썬"
    
    dict = 딕셔너리 (키 : 값)
    {"documents": "...", "answer":"..."}
    
    

노드 함수 vs route 함수의 반환이 다르다.

    
    # node 함수 (search, generate, judge)
    def search(state) -> dict:
    	return {"documents":"..."} # dict 반환
    	
    #route 함수
    def route(state) -> str:
    	return "search" # str(문자열) 반환
    

하는일이 달라서 다름

node = "state를 업데이트" 하는 일  
\-> " 이 키를 이 값으로 바꿔줘" = dict  
\-> {"documents": 검색결과}

route = "다음 갈 곳을 알려주는 일"  
\-> "search gogo" = node 이름 하나 = str  
\-> "search"

#### 질문 2 : Generate 에서 context 가 비면 왜 안될까?

검색을 스킵해 버리면 documents가 "" 그대로 나오게 됨 -> "빈 문서를 근거로 답해" 라는 모순된 지시를 실시
