RAG (Retrieval-Augmented Generation)

*   외부 문서를 검색해 LLM 입력에 넣고, 그 근거로 답변을 생성하는 구조다. (오픈북 시험) LLM이 모르는 최신 정보/내부 문서를 재학습 없이 보완하고 환각을 줄이기 위해 사용한다.
    

전체 흐름

인덱싱 : 문서 로딩 -> 전처리 -> 청킹 -> 임베딩 -> 벡터 DB 저장

질의 : 질문 -> 검색(Retrieval) -> 생성(Generation)

문서 로딩

*   PDF, HTML, JSON 등에서 텍스트를 추출하는 첫 단계다. (형식마다 맞는 파서 필요)
    

PDF 파싱

*   PDF 내부 구조를 해석해 텍스트/표를 추출한다. (문자 좌표로 저장되어 그냥 읽으면 안 됨)
    

청킹 (Chunking)

*   긴 문서를 작은 조각으로 나누는 과정. (통째로 임베딩하면 의미가 희석되므로)
    

    고정 길이: 글자 수로 자르기
    구분자 기반: 줄바꿈/마침표/제목으로
    의미 기반: 주제 바뀌는 지점에서
    부모-자식: 검색은 작게, 답변은 넓게

토큰화 (Tokenization)

*   텍스트를 최소 단위(토큰)로 쪼개는 과정. (숫자로 바꾸기 전 단계) 서브워드 방식이 현재 LLM 표준. 토크나이저가 규칙/사전으로 분리 후 정수 ID 변환.
    

밀집 벡터 (Dense Vector)

*   의미를 담아 모든 차원에 값이 채워진 벡터. (키워드 달라도 의미 검색 가능) Sparse Vector는 대부분 0 -> 정확한 키워드 매칭용.
    

Sentence Transformers

*   문장을 밀집 벡터로 바꾸는 오픈소스 임베딩 라이브러리. (로컬/무료, model.encode())
    

Vector DB

*   고차원 벡터를 저장하고 유사도 검색을 빠르게 하는 특수 DB.
    

HNSW

*   벡터를 계층 그래프로 만들어 빠르게 유사 벡터를 찾는 알고리즘. (전수 비교 X, 정확도 99%+)
    

ChromaDB

*   문서/벡터/메타데이터를 함께 저장하는 가벼운 오픈소스 벡터 DB. (학습/프로토타입용)
    

검색 (Retrieval)

*   질문을 벡터화해 벡터 DB에서 유사한 청크 상위 k개를 찾아오는 단계.
    

생성 (Generation)

*   검색된 문서를 프롬프트에 넣고 LLM이 근거로 답을 만드는 단계. "참고하여"(X) 대신 "문서만을 근거로"(O) -> 환각 감소.
    

RAG 인덱싱

*   로딩 -> 전처리 -> 청킹 -> 임베딩 -> 저장까지, 검색 가능한 상태로 만드는 전체 과정.
    

컨텍스트 윈도우 (Context Window)

*   LLM이 한 번에 처리할 수 있는 최대 토큰 수. 시스템 프롬프트 + 문서 + 질문 + 답변의 합이 한도를 넘으면 안 됨.
    

알렉스 강조 포인트

*   Gen AI를 자동차에 비유 엔진 = 모델 (LLM) 완성차 = RAG, 에이전트 프레임워크 (LangChain / LangGraph) 튜닝 = LLM 최적화 AS(유지보수) = 리눅스, 클라우드 운전 = 서빙
    

*   임베딩: 원핫 -> 밀집 벡터 원핫 인코딩: apple = (0,...,1,...,0), 1만 차원, 대부분 0 (희소) 프로젝션(선형변환)으로 300차원으로 압축 이 변환 가중치가 학습 대상 임베딩 = 벡터가 모인 공간 = 의미 공간
    

*   코사인 유사도 각이 작을수록 유사 cos 0 = 1 -> 값이 1에 가까울수록 유사
    

*   Vector DB = NoSQL의 하나 RDB: 테이블 구조 -> 문법(SQL) 기반 검색 Vector DB: 컬렉션 구조 -> 의미 기반 검색 "자기들은 RDB가 아니다" Text2SQL: 자연어를 SQL로 변환
    

*   검색은 벡터 DB만이 아니다 RDB: 표 구조 GDB: 그래프 구조 (Neo4j, Apache Jena) 벡터 DB는 검색의 한 종류일 뿐
    

*   전처리 비중이 크다 실무에서 전처리 + 라벨링 업무 비중이 상당함 (Scale AI 사례)
    

*   청킹 / 검색 도구 구분자(delimiter): \\n(한 줄), \\n\\n(단락) 정규표현식으로 패턴 분할 HNSW: 빠른 유사 벡터 검색 FAISS, Gemini API 2.5 Flash(무료) 활용 -> 개인프로젝트
