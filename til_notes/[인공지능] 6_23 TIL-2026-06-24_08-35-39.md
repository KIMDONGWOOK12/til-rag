배운 내용 : LangChain RAG 파이프라인 (Text Splitter, 벡터 저장소, Retriever, LangSmith)

Text Splitter

정의 : Document를 작은 Document(chunk)들로 분할하는 표준 인터페이스다.

이유 : Document가 클수록 검색 정밀도가 떨어지고 토큰 비용이 늘어나기 때문

방법 : 분할기를 골라 Document를 넣으면 chunk 리스트로 나오며, 원본 metadata는 각 chunk에 그대로 유지된다.

분할기 종류

RecursiveCharacterTextSplitter : 문단/줄/공백 우선순위로 분할 (가장 많이 씀)

CharacterTextSplitter : 지정한 구분자 하나로 분할

TokenTextSplitter : 토큰 수 기준 분할

MarkdownHeaderTextSplitter : 마크다운 헤더 기준

HTMLHeaderTextSplitter : HTML 헤더 기준

TokenTextSplitter

정의 : 토큰 수를 기준으로 분할하는 분할기다.

이유 : 글자 수와 토큰 수가 비례하지 않기 때문이다. 한국어는 한 글자가 여러 토큰이 되어, 같은 양이어도 영어는 안전한데 한국어는 토큰 한도를 초과할 수 있다.

방법 : tiktoken으로 토큰을 세어 한도 안에서 분할한다.

Embeddings

정의 : 자연어를 벡터로 변환하는 표준 인터페이스다.

이유 : 모델을 바꿔도 임베딩 방식을 따로 바꿀 필요 없이 같은 방식으로 쓰기 위해서다.

방법 : 여러 문서를 한 번에 벡터로 바꾸거나 단일 질의를 벡터로 바꾼 뒤, 질의 벡터와 문서 벡터의 코사인 유사도로 의미 거리를 확인한다.

VectorStore Interface

정의 : 모든 벡터 DB가 따르는 LangChain의 표준 인터페이스(문서 벡터 저장소)다.

이유 : DB 종류와 무관하게 같은 코드로 인덱싱/검색/Retriever 변환을 해서 교체 비용을 줄이기 위해서다.

방법 : 문서를 임베딩해 저장(인덱싱)하고, 질의로 유사도 검색을 하며, 필요하면 Retriever로 변환해 체인에 연결한다.

Croma

정의 : 별도 서버 없이 파이썬 환경에서 쓰는 임베디드 방식의 VDB다.

이유 : RAG 구조를 실습하거나, 자체 서버형 VDB를 쓰기 전에 작은 데이터셋으로 검색 품질을 검증할 때 쓴다.

방법 : 실행 중에는 메모리에 보관하고, 로컬 디렉터리에 데이터를 보존한다.

FAISS

정의 : Meta가 공개한 메모리 기반 고속 유사도 검색 VDB다.

이유 : 대량 벡터 검색을 빠르게 처리하기 위해서다.

방법 : 메모리 기반이라 종료되면 인덱스가 사라지므로(휘발성), 재사용하려면 로컬에 별도로 저장하고 불러와야 한다.

Retriever

정의 : 질문을 받아 관련 있는 Document 리스트를 반환하는 표준 인터페이스다.

이유 : 다양한 검색 방식을 같은 방식으로 다루기 위해서다.

방법 : VectorStore를 Retriever로 변환해 체인에 연결한다.

Ensemble Retriever

정의 : 여러 Retriever의 결과를 가중치로 합쳐 반환하는 Retriever다.

이유 : 키워드 검색과 의미 검색을 함께 써서 서로의 약점을 보완하기 위해서다 (Hybrid Search).

방법 : 여러 Retriever와 각 가중치를 등록해 결과를 합친다.

Multi-Query Retriever

정의 : 하나의 질문을 LLM이 여러 표현으로 바꿔 각각 검색한 뒤 결과를 합치는 Retriever다.

이유 : 질문 표현이 문서와 맞지 않아 검색이 빗나가는 경우를 막기 위해서다 (Query Expansion).

방법 : 기본 Retriever에 LLM을 연결해 질문을 여러 개로 변형한 뒤 검색한다.

Contextual Compression

정의 : 검색된 Document에서 질문과 관련 있는 부분만 추려내는 Retriever다.

이유 : 검색 결과에 섞인 노이즈를 줄여 답변 품질을 높이기 위해서다 (Reranking 계열).

방법 : 기본 Retriever로 문서를 가져온 뒤, 압축기로 관련 없는 부분을 제거한다.

Parent Document Retriever

정의 : 작은 chunk로 검색하되, 반환은 그 chunk가 속한 부모(원본) 문서로 주는 Retriever다.

이유 : 검색 정확도(작게 자름)와 맥락(크게 봄)을 동시에 잡기 위해서다.

방법 : 검색은 작은 chunk로 하고, 반환은 부모 문서로 한다.

LangSmith

정의 : LangChain 앱의 실행을 추적/디버깅/평가/모니터링하는 플랫폼이다.

이유 : 체인이 길어지면 어느 단계에서 문제가 생겼는지 찾기 어렵기 때문이다.

방법 : 각 단계(프롬프트 입력, 모델 응답, 검색 결과)를 자동 기록(Tracing)하고, 출력 품질을 평가한다.

큰 틀

Document에서 시작해 Splitter로 나누고, Embeddings와 VectorStore로 저장하고, Retriever로 검색해 생성하며, LangSmith로 전체를 추적/평가한다.

고급 Retriever들은 결국 검색 품질을 높이는 방법이다. Ensemble은 키워드와 의미를 함께, Multi-Query는 질문을 확장, Contextual Compression은 노이즈 제거, Parent Document는 정확도와 맥락을 동시에 잡는다.
