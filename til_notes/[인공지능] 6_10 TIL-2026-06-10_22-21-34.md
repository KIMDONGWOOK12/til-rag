배운 내용 : Transformer의 Input pipeline부터 self-attention까지 (교재 기준)

**Input Pipeline**

*   자연어 문장이 모델에 들어가기까지의 전처리 흐름이다.
    
*   자연어 문장
    
    *   토크 나이저 ( 문장을 토큰으로 분리 + 정수 ID 변환)
        
    *   토큰 임베딩 ( 정수ID -> 벡터)
        
    *   포지셔널 인코딩 (위치 정보 추가)
        
    *   인코더./디코더 입력
        

**토크나이저(Tokenizer)**

*   입력 텍스트를 분절 규칙에 따라 노큰으로 나누고, 어휘 사전을 참조해 정수 ID로 변환하는 전처리 모듈
    
    *   사용이유 : 신경망은 문자열을 직접 처리하지 못하므로 숫자로 변환해야 함
        
    *   동작방식 :
        
        *   규칙 : 어떻게 텍스트를 나눌지 (단어, 서브워드, 문자 단위)
            
        *   사전 : 단어 -> 정수ID 맵핑 테이블
            
*   예시
    
    *   "어댑터즈는 스사트업코드에서 제공하는 서비스입니다"
        
    *   토큰: \['어', '##댑', '##터', '##즈', '##는', '서비스', '##입니다'\]
        
    *   모델의 어휘 사전에 따라 각 토큰이 고유한 정수 ID로 변환됨
        

    # 사용 방법
    from tansformers import Autotokenizer
    
    tokenizer = AutoTokenizer.from_pretrained("bert-base-multilingual-cased")
    
    encoded = tokenizer(text)
    
    print(encoded["input_ids"])    # 정수 ID 시퀀스

**토큰 임베딩(Token Embedding)**

*   정수 ID로 표현된 토큰을 고정 차원의 밀집 벡터(dense vector)로 변환하는 연산
    
    *   사용 이유: 정수 ID는 단순한 번호이므로 의미 관계를 표현하지 못하고, 벡터로 변환해야 모델이 의미 유사성을 학습할 수 있음
        
*   d\_model : 토큰 하나를 표현하는 벡터의 차원 수
    

**포지셔널 인코딩(Positional Encoding)**

*   시퀀스 내 위치 정보를 벡터 형태로 반영하여 모델이 토큰 순서를 구분할 수 있게 하는 기법이다.
    
    *   사용 이유
        
        *   Transformer는 순환 구조가 없어 순서를 자체적으로 알 수 없음
            
        *   RNN은 순서대로 읽으므로 위치를 자동으로 알지만, Transformer는 병렬 처리라 따로 주입 필요
            
    *   사용 방법
        
        *   사인/코사인 함수로 위치별 벡터 생성 -> 토큰 임베딩에 더함
            
*   입력 = 토큰 임베딩 + 포지셔널 인코딩
    
*   최근은 RoPE 같은 방식도 사용
    

**인코더(Encoder)**

*   입력 문장의 각 토큰을 문장 전체의 문맥이 반영된 벡터로 바꾸는 Transformer의 입력 처리 블록이다.
    
    *   사용 이유 : 입력 텍스트의 전체 문맥을 압축된 벡터 표현으로 만들어 후속 모듈이 사용할 수 있게 하기 위해
        
*   한 층의 구조( 크게 두 단계로 구성)
    

*   Multi-Head Self-Attention -> Add & Norm -> Feed-Forward Network -> FFN -> Add & Norm
    
*   위 구조를 통해 N층 반복
    

*   출력 : 입력과 같은 shape이지만 문맥이 반영된 벡터 시퀀스
    

    encoder_input  shape: [batch, seq_len, d_model]
    encoder_output shape: [batch, seq_len, d_model]

**디코더 (Decoder)**

인코더의 출력과 이전까지 생성된 토큰을 참조하여 다음 토큰을 순차적으로 생성하는 Transformer의 구성 요소다.

*   사용 이유
    
    *   인코더가 만든 입력 문장 표현을 바탕으로 목표 시퀀스를 한 토큰씩 자기회귀적으로 생성하기 위해
        
*   한 층의 구조 (인코더와 차이점: Cross-Attention 추가)
    
*   자기회귀(autoregressive) : 자신이 만든 출력값을 다음 입력으로 다시 사용하는 방식
    

**어텐션 메커니즘 (Attention Mechanism)**

현재 토큰이 참고해야 할 다른 토큰을 찾고, 관련성이 높은 정보에 더 큰 비중을 두어 새로운 표현을 만드는 연산 방식이다.

*   사용 이유
    
    *   문장 안에서 멀리 떨어져 있어도 의미상 중요한 토큰을 직접 참고하기 위해
        
*   핵심 3요소: Q, K, V
    

    Query (Q): 현재 토큰이 찾고 싶은 정보
    Key   (K): 각 토큰이 비교될 기준
    Value (V): 실제로 가져올 정보  

*   동작 흐름
    

    1. Q와 K를 비교해 관련도 점수 계산
    2. softmax로 비중으로 변환
    3. V를 비중에 따라 가중합
    4. 현재 토큰의 새로운 표현 생성

**Self-Attention**

현재 토큰이 같은 문장 안의 다른 토큰들을 얼마나 참고해야 하는지 계산하고, 그 결과를 반영해 현재 토큰의 표현을 다시 만드는 연산

*   사용 이유
    
    *   토큰 하나만으로는 의미를 확정할 수 없으므로, 문장 전체와의 관계를 반영한 문맥 기반 표현을 만들기 위해
        

    "Startupcode is a company, and it provides a service."
    
    it -> Startupcode와 관련도 높음
       -> Startupcode의 Value를 더 많이 반영
       -> "it"이 Startupcode를 가리킨다는 문맥 표현 생성

*   RNN vs Self-Attention
    

    RNN          -> 순차 처리, 멀리 떨어진 정보가 여러 단계를 거쳐 약해짐
    Self-Attention -> 모든 토큰을 동시에 참고, 거리에 관계없이 직접 계산

**멀티헤드 어텐션 (Multi-Head Attention)**

서로 다른 Q, K, V 가중치 행렬로 어텐션을 여러 번 계산해 다양한 관계를 동시에 포착하는 연산이다.

*   사용 이유
    
    *   단일 어텐션은 한 가지 관점에서만 관계를 봄
        
    *   여러 헤드를 사용하면 문법, 감정, 의미 등 다양한 관점에서 관계를 포착 가능
        
*   동작 방식
    

    Head 1: W_1Q, W_1K, W_1V -> O1
    Head 2: W_2Q, W_2K, W_2V -> O2
    ...
    [O1 | O2 | ...] × W_O -> 최종 출력

*   각 헤드의 가중치는 랜덤으로 초기화 후 학습
