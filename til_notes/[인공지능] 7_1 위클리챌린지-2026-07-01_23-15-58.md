위클리챌린지 과제1 - 7주차 RAG를 LangGraph StateGraph로 마이그레이션

간단하게 정리 후 한 주 마무리 시간에 상세하게 정리 예정

*   7주차에 LangChain LCEL로 만든 RAG 파이프라인(baseline.py)을 LangGraph의 StateGraph 구조로 옮겼다.
    
*   7주차 폴더를 통째로 복사해 8주차 폴더를 만들고, 그 안에서 작업했다.
    

인덱싱(문서 로딩, 분할, 임베딩, Chroma 저장)과 retriever/prompt/llm 정의는 그대로 재사용하고, 그 아래 체인 부분만 StateGraph로 교체했다.

기존 LCEL 코드는 지우지 않고 주석 처리해서 남겨뒀다.

마이그레이션 내용

*   State 정의
    

    class RAGState(TypedDict):
        question: str
        documents: str
        answer: str

*   Node 2개로 분리
    

    search_node : retriever.invoke로 문서 검색 -> {"documents": ...} 반환
    generate_node : prompt+llm+parser 체인으로 답변 생성 -> {"answer": ...} 반환

*   각 노드는 state를 직접 수정하지 않고, 바뀐 키만 dict로 반환하도록 작성했다. (여러 노드가 동시에 state를 고칠 때 충돌 나는 걸 방지하기 위함이라고 배웠다.)
    
*   Edge 연결
    

    graph.add_edge(START, "search")
    graph.add_edge("search", "generate")
    graph.add_edge("generate", END)

*   compile() 후 app.invoke({"question": ..., "documents": "", "answer": ""}) 형태로 실행하도록 바꿨다. (기존에는 rag.invoke("질문") 처럼 문자열 하나만 넣었는데, StateGraph는 State 전체를 딕셔너리로 넣어야 한다.)
    

평가 코드의 target 함수도 rag.invoke 대신 app.invoke를 쓰도록 수정했다. 평가자(contains\_expected\_keyword, llm\_judge)와 evaluate() 호출부는 그대로 뒀다.

결과

*   "파이썬이 뭐야?" 질문으로 실행한 결과, 7주차 LCEL 버전과 동일한 내용의 답변이 나왔다. (귀도 반 로섬, 1991년, Monty Python 유래 등)
    
*   LangSmith Dataset 평가(파이썬/자료구조/알고리즘 3문항, wiki-dev-rag-eval)도 정상적으로 3건 다 통과했다. 실험명: v2-dev-1dc76887
    

*   트러블슈팅
    

    StateGraph() 를 스키마 없이 생성해서 에러 -> StateGraph(RAGState)로 수정
    generate 노드를 등록할 때 자동완성 실수로 GeneratorExit(파이썬 내장 예외)를 넣어서 에러 -> 직접 만든 generate 함수로 수정

두 곳 수정 후 정상 작동을 확인했다.
