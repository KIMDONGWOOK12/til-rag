구조개선과 소프트웨어 엔지니어링 (아키텍쳐 & 디자인 패턴)

*   왜 구조를 개선하는가?
    
    *   복잡도 제어 : 한 파일에 유저, 게시글, 댓글 로직을 모두 넣으면 코드가 엄청 커짐
        
    *   기능의 변화 없이 구조만 변경하여 가질 수 있는 이점은 재사용성 향상과 유지보수 효율화함
        

*   엔지니어의 성장 단계 :
    
    *   주니어 -> 시니어 -> 아키텍트
        

Router-controller-model 패턴

*   Router : http 요청을 최초로 받아 URL과 MEthod에 따라 적절한 Controller로 분기해주는 역할
    
*   Controller : http요청 파라미터를 추출하고 응답 형식을 결정하며, 실제 비즈니스 처리는 서비스에 위임
    
*   Service : 중복 검사, 암호화 등 비즈니스 흐름을 결정하는 핵심 계층
    
*   Repository /model : Db에 직접 접근하여 sql을 실행하거나 데이터를 조회-저장-수정-삭제하는 계층
    

웹 백엔드의 핵심 주변 기술

*   미들 웨어
    
    *   요청이 라우터에 돨하기 전과 응당이 나가는 전 과정을 감싸는 전역 공통 소프트웨어
        
    *   CORS 처리, rate limiting 등 애플리케이션 전반에 공통 적영되어야 하는 정책
