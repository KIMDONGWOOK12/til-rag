HTTP : 웹의 기본 통신 규약

*   클라이언트와 웹 서버가 링크나 데이터 같은 하이퍼텍스트를 주고받기 위해 만든 세꼐 공통의 표준 규칙
    
*   표준화된 규칙(HTTP)이 없다면 컴퓨터마다 통신 방법이 달라 매번 새로 개발해야 한다. HTTP 덕분에 전 세계 모든 웹사이트 브라우저가 자유롭게 소통할 수 있다.
    

HTTP Message : 데이터 소통의 단위

*   클라이언트와 서버가 주고받는 통신의 기본 단위
    
*   메시지 필수 구조 4가지:
    
    *   시작줄(Start Line): 이 요청/응답이 성공했는지, 어떤 메서드인지 적는 첫 줄
        
    *   헤더(Headers): 메시지 본문의 크기, 형식, 보낸 사람의 브라우저 정보 등 부가 데이터(Metadata)가 담긴 곳
        
    *   빈줄(Empty Line) : 헤더가 끝나고 본문이 시작됨을 알리는 구분선
        
    *   본문(Body): 실제 전송하려는 핵심 데이터 (HTML 문서, JSON 등)
        

HTTP Request Method : 서버에서 내리는 명령 종류

*   웹 서버에서 구체적으로 어떤 작업을 원하는지 명확하게 지시하기 위한 규칙
    
    *   GET : 리소스 조회
        
    *   POST : 리소스 생성
        
    *   PUT : 리소스 전체 수정
        
    *   PATCH : 리소스 부분 수정
        
    *   DELETE : 리소스 삭제
        

HTTP Status Code : 서버의 답변 상태

*   클라이언트의 요청에 대해, 서버가 처리 결과를 3자리 숫자로 명확하게 알려주는 암호
    
*   반드시 알아야할 핵심 번호대:
    
    *   2xx(예: 200) : 요청이 잘 처리됨
        
    *   4xx(예:400) : 클라이언트 오류
        
    *   5xx(예:500) : 잘 요청했는데 서버가 고장남
        
    *   300 : 리다이렉션
        

HTTP URL : 웹 리소스의 이정표

*   웹상에 존재하는 수많은 자원(HTML, Image 등)의 고유한 집 주소
    
    *   스키마 : 통신 방식 규칙 (https://)
        
    *   도메인 & 포트 : 찾아갈 컴퓨터 주소(Orbit.com)
        
    *   리소스 경로(path) : 서버 컴퓨터 내부의 폴더/파일 위치 (/post)
        
    *   매개변수(parameter): 추가적인 요청 조건 (?id=1)
