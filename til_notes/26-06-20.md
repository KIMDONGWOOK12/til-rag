# 오늘 한 것

위키피디아 문서를 데이터로, Gemini API와 ChromaDB를 써서 문서 로딩부터 응답 생성까지 RAG 파이프라인을 직접 구축했다.

질문을 던지면 위키 문서를 검색해 그 근거로 답하는 것까지 동작 확인했다.

## 전체 구조

### \[인덱싱 - 미리 준비\]

위키 수집 -> 청킹 -> 임베딩 -> ChromaDB 저장

### \[질의 - 실시간\]

질문 -> 검색(유사 청크) -> Gemini 생성

## 사용한 도구

LLM/임베딩 : Gemini API (gemini-2.5-flash, gemini-embedding-001)

벡터 DB : ChromaDB (코사인 유사도)

데이터 : 한국어 위키피디아 (주제 20~34개, 약 48만 자)

환경 : Google Colab

## 총 5단계로 진행

1.  데이터 수집 wikipedia 라이브러리로 주제별 본문을 받아 big\_data.txt로 저장.
    
2.  청킹 문단(\\n\\n) 기준으로 분할, 50자 이하 짧은 청크는 제외(노이즈 방지). -> 약 887개 청크 생성 (연습용으로 300개만 사용)
    
3.  임베딩 + 저장 (인덱싱) 각 청크를 Gemini 임베딩으로 벡터화해 ChromaDB에 저장. 배치(20개씩)로 나눠서 천천히 저장.
    
4.  검색 질문을 같은 임베딩 모델로 벡터화 -> ChromaDB에서 유사 청크 Top-3 검색
    
5.  생성 검색된 청크를 프롬프트에 넣고 "문서만을 근거로" 답하게 해 Gemini 호출
    

핵심 코드 (질의 함수)

    def rag(question):
        # 1. 검색
        q_emb = embed_texts([question])[0]
        results = collection.query(query_embeddings=[q_emb], n_results=3)
        contexts = results["documents"][0]
    
        # 2. 생성
        ctx = "\n---\n".join(contexts)
        prompt = f"""다음 문서만을 근거로 질문에 한국어로 답하세요.
    문서에 없으면 '문서에서 찾을 수 없습니다'라고 하세요.
    
    [문서]
    {ctx}
    
    [질문]
    {question}"""
        r = client.models.generate_content(
            model="gemini-2.5-flash", contents=prompt
        )
        return r.text

## 1-1 하는 과정 중 막혔던 점과 해결

*   위키 수집이 0개로 나옴 원인: page.links로 링크를 긁는 과정에서 막힘 해결: 링크 확장을 빼고 주제를 직접 나열, auto\_suggest=False 추가 (동음이의어 에러 방지)
    
*   429 RESOURCE\_EXHAUSTED (무료 티어 제한) 원인: 임베딩을 한 번에 많이/빠르게 요청해 분당 한도 초과 해결: 배치 크기를 50 -> 20으로 줄이고, 요청 간 대기 시간을 늘림 막히면 자동으로 30초 쉬고 재시도하도록 처리
    
*   API 키 노출 원인: 코드에 키를 직접 적어 노출됨 해결: 노출된 키는 폐기/재발급, 코랩 비밀키 기능(userdata)으로 관리 -> 코드에 키가 안 보이게
    
*   터미널 vs 노트북 혼동 파일(big\_data.txt)은 공유되지만 변수(chunks 등)는 공유 안 됨 -> RAG 작업은 노트북 셀에서 일관되게 진행해야 함
