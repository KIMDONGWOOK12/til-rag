# 내일 최종적으로 이번주 위클리챌린지 정리해서 상세하게 정리해둘 예정입니다.

## 오늘 한 일

콜랩에서 만든 RAG를 VS Code로 옮기고, FastAPI 서버와 LangSmith 평가를 붙였다.

위클리챌린지 3과제(마이그레이션 / FastAPI 배포 / LangSmith)를 전부 완료했다.

## VS Code 마이그레이션

정의 : 마이그레이션은 콜랩에서 실험한 코드를 정식 프로젝트(.py 파일)로 옮기는 것이다.

이유 : 콜랩은 실험용이고, 깃허브 제출과 포트폴리오에는 정리된 .py 파일이 필요하다.

방법 : 가상환경(.venv)을 만들고 필요한 패키지를 설치한 뒤, 역할별로 파일을 나눈다.

    main.py      FastAPI 서버 (질문 받아 답변)
    baseline.py  RAG 구축 + 평가
    .env         API 키 보관 (깃허브에 안 올림)
    .gitignore   .env, .venv 등 제외

## FastAPI 배포

정의 : FastAPI는 파이썬으로 REST API 서버를 만드는 웹 프레임워크다.

이유 : RAG를 코드 안에서만 쓰지 않고, 외부에서 질문을 보내 답을 받게 하려면 API가 필요하다.

방법 : POST 방식으로 질문을 받아 RAG를 실행하고 답변을 돌려준다.

    @app.post("/query")
    질문(question)을 받아 rag.invoke로 답변(answer) 반환
    -> uvicorn main:app --reload 로 실행
    -> localhost:8000/docs 에서 테스트

## lifespan으로 RAG 한 번만 만들기

정의 : lifespan은 서버가 켜질 때 한 번만 실행되는 초기화 코드다.

이유 : 질문마다 RAG를 새로 만들면 매번 인덱싱해서 느리다. 서버 시작 시 한 번만 만들어 재사용한다.

방법 : 앱 시작 시 build\_rag\_chain()을 호출해 app.state에 저장해 둔다.

## LangSmith 평가 (Dataset)

정의 : Dataset 평가는 질문과 기대 답변을 모아두고, RAG 답변을 자동 채점하는 것이다.

이유 : RAG가 잘 답하는지 사람이 일일이 보지 않고, 점수로 객관적으로 확인하기 위함이다.

방법 : 질문과 기대 답변을 Dataset으로 만들고, 평가자(Evaluator)로 채점한다.

    질문 3개 + 기대 답변 등록
    평가자 2종으로 채점 후 evaluate 실행

### 평가자 두 종류 비교

정의 : 평가자는 RAG 답변을 채점하는 기준이다. 두 방식을 비교했다.

    키워드 매칭   기대 답변의 단어가 들어있나 (글자 비교)
    LLM-as-Judge  의미가 맞는지 LLM이 판단 (의미 비교)

결과 : 키워드 매칭 0.33, LLM 평가 1.00 으로 차이가 났다.

이유 : 키워드 매칭은 "특화"와 "중점"처럼 뜻이 같아도 글자가 다르면 0점을 준다. LLM 평가는 의미를 보고 맞다고 판단한다.

결론 : 단순 키워드 매칭은 한계가 있고, 의미 평가에는 LLM-as-Judge가 더 정확하다.

## 터미널 대화형 챗봇

정의 : input()으로 질문을 받아 즉시 답하는 반복 루프다.

방법 : while 루프 안에서 input으로 질문을 받아 rag.invoke로 답한다.

    질문> 입력 -> 답변 출력 -> 반복
    q 입력 시 종료

### 트러블슈팅

환경변수만으로는 터미널 질문이 LangSmith에 안 떴다. .env에 LANGSMITH 설정을 넣고 load\_dotenv로 불러오니 정상 기록됐다.

평가 결과는 Datasets 메뉴, 일반 질문 기록은 Tracing 메뉴로 보는 위치가 달랐다.
